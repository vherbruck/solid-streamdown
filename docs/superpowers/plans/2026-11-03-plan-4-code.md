# Plan 4: `@solid-streamdown/code`

> **For agentic workers:** execute task by task. Each task ends green (`bun run typecheck && bun run build && bun run test`, plus the hydration check in Task 2) and with one commit.

**Status:** In progress, 2026-11-03. The owner said to proceed; no owner decisions are open.

**Goal:** Ship upstream's Shiki code-highlighting plugin as `packages/streamdown-code` (`@solid-streamdown/code`), and prove it works end to end with core: highlighted tokens, stable streaming, and server rendering then hydration.

**Architecture:**
- Upstream's `packages/streamdown-code/index.ts` is framework-free: Shiki, a JavaScript regex engine, a token cache and incremental tokenizing. It is copied verbatim.
- Core already implements the consumer side in plan 2 (`lib/code-block/highlighted-body.tsx`), against the structural `CodeHighlighterPlugin` type in `lib/plugin-types.ts`. Plugins do not import core, and core does not import plugins.

**Upstream:** `/tmp/streamdown-upstream` at `c5e44d8`, `packages/streamdown-code` (`@streamdown/code` 2.0.0).

## Constraints

- Plans 1 to 3's constraints apply: Apache-2.0, headers on ported files, nothing from PR #5, no React anywhere.
- **Dependencies:**
  - `shiki@^4.4.3`, as upstream pins it.
  - No peer dependencies. Upstream's only one is `react`, which its code never imports. Neither does ours import Solid, so declaring `solid-js` would be false.
- Benchmarks (`__benchmarks__`) are not ported (spec non-goal).
